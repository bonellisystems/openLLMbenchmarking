Bug 2 (line 14, subtle -- silent cross-well corruption): `def

default argument values are evaluated exactly ONCE, when the function is defined, and that

`alerts`, so all wells processed inside one `generate_daily_report` run share the SAME
underlying list across calls -- it never gets reset between wells. Concretely: well A's
overpressure readings get appended to the shared list; when well B is processed next, its
overpressure readings get appended to that SAME list (which still has well A's entries in
it), so `len(events)` for well B is inflated by however many events well A had, and well C's
count is inflated by both A's and B's. No exception is ever raised -- the report just quietly
contains wrong `overpressure_events` counts for every well after the first, in the same run.

def flag_overpressure_events(readings, alerts=None):

call that doesn't explicitly pass `alerts` gets its own new list.

### 🔍 Bug 1: **Incorrect use of mutable default argument**

#### 📍 Line: **14**
```python

```

#### ✅ **Bug Description:**
The function `flag_overpressure_events` uses a **mutable default argument** (`alerts=[]`). In Python, default arguments are evaluated once at function definition time, not each time the function is called. This can lead to **shared state** between function calls.

#### ❌ What happens:
If you call `flag_overpressure_events` multiple times without explicitly passing `alerts`, the same list object is reused. So, for example:
- First call adds values to `alerts`
- Second call reuses the same list and continues appending to it.

#### 🔧 **Fix:**
Change the default argument to `None`, and create a new list inside the function if needed.

```python
def flag_overpressure_events(readings, alerts=None):

        alerts = []

        if psi > ALERT_THRESHOLD_PSI:
            alerts.append(psi)
    return alerts
```

---

### 🔍 Bug 2: **Silent corruption when handling multiple wells**

#### 📍 Line: **23**
```python
events = flag_overpressure_events(readings)
```

#### ✅ **Bug Description:**
This line calls `flag_overpressure_events` **without passing `alerts`**, so it will use the default `alerts=[]`. Because of the previous bug (mutable default), this list is shared across all wells.

Hence, for multiple wells, the list of overpressure events gets contaminated with data from all wells — especially if multiple wells have overpressure events.

If one well has overpressure events and another one doesn't, the second well still modifies the same `alerts` list, causing incorrect data to appear in the final result.

Explicitly pass a fresh list for each well or ensure that `flag_overpressure_events` does not mutate any shared state.
