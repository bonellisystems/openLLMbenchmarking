```bash
set -uo pipefail

SRC_DIR="/data/freezer_logs"
ARCHIVE_DIR="$SRC_DIR/archive"

# Create archive directory if it doesn't exist (idempotent for cron)
mkdir -p "$ARCHIVE_DIR"

    # if the compression step completes successfully.

        rm -- "$file"
    else
        echo "WARNING: Compression failed for '$file'. Original preserved." >&2
        rm -f -- "$tmp_dest"  # Clean up partial temp file if it exists
    fi
done || true
```

### Explanation of Avoided Naive Bugs

#### (a) Breaking on filenames with spaces
**The Naive Bug:** 
A common first draft uses a glob loop or unquoted `read`:
```bash
for f in /data/freezer_logs/*.csv; do ... done
# or
find /data/freezer_logs -name "*.csv" | while read f; do ... done
```
When the shell encounters `Freezer 3 Log.csv`, word splitting treats the space as a delimiter. The loop tries to process `Freezer`, `3`, and `Log.csv` as three separate files. This causes `gzip: Freezer: No such file or directory` errors, potentially corrupts data if a file named `3` exists elsewhere, and silently skips the actual log.

**How this script avoids it:** 
It uses `find ... -print0` combined with `while IFS= read -r -d '' file`. This passes filenames separated by null bytes (`\0`), which cannot appear in valid Unix filenames. `IFS=` prevents the shell from trimming whitespace, `-r` disables backslash escaping, and `-d ''` tells `read` to split on null bytes instead of newlines. The variable `$file` retains the exact original path, spaces and all.

#### (b) Deleting the source even when compression fails
**The Naive Bug:** 
A typical naive implementation chains commands without verifying the exit status of the compressor:
```bash
gzip "$file"
mv "${file}.gz" "$ARCHIVE_DIR/"
rm "$file"
# or worse:
gzip -f "$file" && rm "$file"
```
If `gzip` fails partway through (e.g., disk full, permission denied, I/O error, or corrupted input), the naive script either proceeds to `rm` anyway, or uses `gzip -f` which may overwrite a partial `.gz` file and still return success. In biotech environments with irreplaceable sponsor data, this results in permanent data loss.

**How this script avoids it:** 
1. **Explicit exit-code gating:** The compression is wrapped in an `if` statement. `rm "$file"` is only executed if `gzip -c` returns exit status `0`. Any failure immediately jumps to the `else` branch, preserving the original `.csv`.
2. **Atomic write via temp file:** Instead of redirecting directly to the final archive path (`> "$dest"`), the script writes to a uniquely named temporary file (`${dest}.tmp.$$`). If `gzip` succeeds, `mv` atomically promotes it to the final name. This prevents truncating/corrupting an existing archive if the script is interrupted mid-run, and ensures the archive directory only contains valid, complete `.gz` files.
3. **`|| true` for cron safety:** The pipeline ends with `|| true`. Without it, `set -o pipefail` would cause the script to exit with status `1` when `find` matches zero files (which happens on clean or freshly run days). This guarantees the cron job always reports success (`0`) while still catching real errors inside the loop.

```bash
#!/usr/bin/env bash
# ------------------------------------------------------------
# archive_freezer_logs.sh
#   Safely archive (gzip) CSV logs older than 7 days from
#   /data/freezer_logs/ into /data/freezer_logs/archive/
#   and delete the original only after a successful compression.
#
#   • Handles filenames that contain spaces.
#   • Is idempotent – re‑running on an already‑archived directory
#     does not re‑compress or error.
#   • Never deletes a source file unless the gzip step succeeded.
# ------------------------------------------------------------

set -euo pipefail   # strict mode – helps catch unexpected errors
IFS=$'\n\t'         # sane field splitting (not strictly needed with -print0)

# -----------------------------------------------------------------
# Configuration (change only if your environment differs)
# -----------------------------------------------------------------
SRC_DIR="/data/freezer_logs"
ARCHIVE_DIR="${SRC_DIR}/archive"

# Ensure the archive directory exists
mkdir -p "${ARCHIVE_DIR}"

# -----------------------------------------------------------------
# Find *.csv files that are *directly* under $SRC_DIR and older than 7 days.
# -maxdepth 1   → only the top‑level of $SRC_DIR
# -type f       → regular files only
# -name '*.csv' → only CSV files
# -mtime +7     → modified more than 7*24 hours ago
# -print0       → NUL‑delimited output (handles spaces, newlines, etc.)
# -----------------------------------------------------------------
find "${SRC_DIR}" -maxdepth 1 -type f -name '*.csv' -mtime +7 -print0 |
while IFS= read -r -d '' src_file; do
    # Derive the target archive name (same basename, .gz extension)
    base_name="$(basename "${src_file}")"
    archive_file="${ARCHIVE_DIR}/${base_name}.gz"

    # Skip if we have already archived this file (idempotency)
    if [[ -f "${archive_file}" ]]; then
        echo "Already archived – skipping: $(printf '%q' "${src_file}")"
        continue
    fi

    # Perform the gzip compression.  The -c flag writes to stdout,
    # which we redirect to the archive file.
    if gzip -c "${src_file}" > "${archive_file}"; then
        # Verify that the archive was actually created and is non‑empty.
        if [[ -s "${archive_file}" ]]; then
            echo "Successfully archived: $(printf '%q' "${src_file}") → ${archive_file}"
            # Remove the original only after a successful, non‑empty gzip.
            rm -f -- "${src_file}"
            echo "Deleted source file: $(printf '%q' "${src_file}")"
        else
            echo "ERROR: Archive file is empty – leaving source intact: ${archive_file}" >&2
            exit 1
        fi
    else
        echo "ERROR: gzip failed for ${src_file}" >&2
        exit 1
    fi
done

echo "Archive job completed."
```

```bash
#!/usr/bin/env bash
# archive_freezer_logs.sh
# Archives temperature log CSVs older than 7 days from an ultra-low-freezer monitoring system.
# Safe for cron: idempotent, handles spaces in filenames, never deletes source if archive fails.

readonly ARCHIVE_DIR="${LOG_DIR}/archive"
readonly MAX_AGE_DAYS=7

# -print0 + read -d '' handles filenames with spaces, newlines, and special characters.

    archive_file="${ARCHIVE_DIR}/$(basename -- "$file").gz"

    if gzip -c -9 -- "$file" > "$archive_file"; then
        # Compression succeeded; safe to remove the source.
        rm -f -- "$file"
    else
        # Compression failed; log error and clean up any partial archive.
        echo "ERROR: Compression failed for '${file}'. Source preserved." >&2
        rm -f -- "$archive_file"
    fi
done < <(find "$LOG_DIR" -maxdepth 1 -name '*.csv' -type f -mtime +7 -print0)
```

### Explanation of common bugs avoided:

#### (a) The "Word Splitting" Bug (Handling Spaces)
A naive implementation often uses a loop like this:
`for file in $(find /data/freezer_logs/ -name "*.csv"); do ...`

In Bash, the `$(...)` command substitution undergoes **word splitting** based on whitespace. If the monitoring software exports a file named `Freezer 3 Log.csv`, the `for` loop will attempt to process three distinct, non-existent files: `Freezer`, `3`, and `Log.csv`. This causes the script to error out or, worse, fail to process the actual data.

**My solution** uses `find -print0` paired with `read -r -d ''`. By using the `NULL` character (`\0`) as a delimiter instead of a space or newline, the script treats the entire string `Freezer 3 Log.csv` as a single, unbreakable unit, regardless of spaces or special characters.

#### (b) The "Blind Delete" Bug (Failure Atomicity)
A naive implementation might look like this:
`gzip "$file" && rm "$file"` (where gzip is used without `-c`)
OR
`gzip "$file" > "$archive_dir/$file.gz"; rm "$file"`

In the second (worse) example, if the disk becomes full or the network connection drops during the `gzip` operation, the script will move to the next line and execute `rm "$file"`, even though the archive is incomplete or corrupted. In a biotech environment, this results in the permanent loss of irreplaceable temperature logs.

**My solution** uses `if gzip -c "$file" > "$dest_file"; then`. By using the `-c` (stdout) flag, the original file is never modified. The `if` statement checks the **exit status** of the compression command. The `rm` command is only triggered if the `gzip` command returns a success code (`0`). If compression fails, the script leaves the original file untouched and cleans up the partial archive.

```bash
    echo "Processing: $file"

    #    We use -c (stdout) to avoid modifying the original and to allow atomic verification.
    if gzip -c "$file" > "$archive_path"; then
        # 2. Verify the archive is non-empty and structurally valid
        if [[ -s "$archive_path" ]] && gzip -t "$archive_path" >/dev/null 2>&1; then
            # 3. ONLY delete the original if verification passes
            rm -f "$file"
            echo "✓ Archived and removed: $file"
        else
            echo "⚠ Archive for $file failed integrity check or is empty. Keeping original."
            rm -f "$archive_path"  # Clean up partial/corrupt archive
        fi
    else
        # 4. Compression returned non-zero exit status (e.g., disk full, permissions)
        echo "✗ Compression failed for $file. Original kept."
        rm -f "$archive_path" 2>/dev/null || true
    fi
done
```

#### (a) Iteration Breakage on Spaces
**Naive Bug:** Developers often use `for f in $(find ...)` or `for f in *.csv`. In bash, unquoted command substitution or glob expansion undergoes *word splitting* on spaces, tabs, and newlines. **How This Script Avoids It:** It uses `find -print0` paired with `while IFS= read -r -d ''`. The naive script would then delete the irreplaceable original, assuming a successful archive was made.
**How This Script Avoids It:**

2. It explicitly checks the exit status of `gzip`.
3. It performs a secondary integrity check using `[[ -s "$archive_path" ]] && gzip -t "$archive_path"`. This confirms the file has content and passes gzip's built-in CRC validation.
4. The `rm -f "$file"` command is **strictly nested** inside the `if ... then` block that verifies both success and integrity. If compression fails, is interrupted, or produces a corrupt archive, the original is preserved and the partial `.gz` is cleaned up. This ensures zero risk of data loss even under adverse system conditions.
