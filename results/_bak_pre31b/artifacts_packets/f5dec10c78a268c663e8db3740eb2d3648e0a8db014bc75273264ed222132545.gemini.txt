## 1. Proposed File/Folder Taxonomy

### 1.1 Folder Hierarchy (by quarter & line)

```
/ScanLogs/
   /YYYY_QQ/
       /Line01/
       /Line02/
       /Line03/
```

* **YYYY** – Four‑digit calendar year (e.g., `2025`).  
* **QQ** – Quarter identifier (`01`, `02`, `03`, or `04`).  

**Why?**  
- Isolates data by quarter, matching the existing lot‑counter reset policy.  
- Separates each production line into its own sub‑folder, preventing any cross‑line file name collisions.

### 1.2 Filename Pattern (self‑describing)

```
Lot_<Line>_<YYYYQQ>_<Seq>.csv
```

* **Line** – Two‑digit line identifier (`01`, `02`, `03`).  
* **YYYYQQ** – Concatenation of the year and quarter (e.g., `202503` for Q3 2025).  
* **Seq** – The **running 4‑digit lot counter** that resets each quarter **per line** (`0001`, `0002`, … `9999`).  
* **Extension** – Keep `.csv` (or `.log` if preferred) for consistency.

**Resulting example filenames**

| Production Line | Quarter | Counter | Filename |
|-----------------|---------|---------|----------|
| Line 1          | Q3 2025 | 0075    | `Lot_01_202503_0075.csv` |
| Line 2          | Q3 2025 | 0032    | `Lot_02_202503_0032.csv` |
| Line 3          | Q3 2025 | 0199    | `Lot_03_202503_0199.csv` |

**Properties**

* **Uniqueness** – The combination of *Line* + *Quarter* + *Seq* is guaranteed unique because the counter restarts **per line** each quarter.  
* **Self‑describing** – Anyone looking at the file sees exactly which line, quarter, and lot number it represents.  
* **No overwrites** – Each new lot creates a new file; the old files remain untouched.  

### 1.3 Optional Metadata Header (inside the CSV)

For extra safety, each CSV can start with a small metadata block (e.g., CSV comment lines or a JSON header) that repeats the same identifiers:

```csv
# Line,YearQuarter,Sequence
01,202503,0075
Timestamp,LotID,ProductCode,Operator,...
2025-08-17T08:12:03,0075,CHKN001,J.Doe,...
```

This makes the file **human‑readable at a glance** and future‑proofs against any accidental moves.

## 3. Handling the Already‑Recorded, Ambiguous Lots

Because the lots have **already shipped** under the same 4‑digit number on different lines, we cannot simply rename the existing files—doing so would create a discrepancy between the shipped product records and the historical file system, which is unacceptable for USDA traceability.

### 3.1 Create a **“Collision Resolution Layer”**

1. **Preserve the original files** exactly as they exist (do not delete or rename).  
2. **Add a “collision‑resolved” copy** for each ambiguous lot that embeds the line identifier in its name, **but keep the original untouched** for audit integrity.

   Example:  
   - Original (ambiguous) file: `lot_log.csv` (overwritten each lot).  
   - New resolved copy for Line 2, Q3 2025, lot 0234: `Lot_02_202503_0234_collision.csv`.

3. **Log the mapping** in a master CSV (`LotCollisionMap.csv`) stored in the root of `/ScanLogs/`:

   ```csv
   OriginalFilename,OriginalTimestamp,Line,YearQuarter,Seq,CollisionResolvedFilename
   lot_log.csv,2025-07-12T14:03:00,02,202503,0234,Lot_02_202503_0234_collision.csv
   ```

   This map provides a **traceable audit trail** showing which ambiguous file corresponds to which physical line and lot number.

### 3.2 Communicate the Mapping to Stakeholders

* **USDA Auditors** – Provide the `LotCollisionMap.csv` upon request; explain that the original files are retained for legal preservation, while the new names reflect the true provenance.  
* **Internal Quality & Shipping Teams** – Update SOPs to reference the resolved filenames for any future traceability queries.  
* **Documentation** – Add a section in the plant’s “Lot Tracking Procedure” describing:  
  * The old ambiguous scheme.  
  * The new unique taxonomy.  
  * How collision‑resolved files are generated and where the mapping table lives.

### 3.3 Prevent Future Collisions

The new per‑line counter (Step 1.2) **eliminates the root cause**: each line now has its own independent 4‑digit counter that resets quarterly. Even if the plant later decides to reuse a numeric range, the line prefix guarantees distinction.

1. **During an audit** the USDA inspector asks for “Lot 0010”.  
2. The auditor consults the *disambiguation table* and sees that there are two entries, one for each line.  
3. The auditor requests the *InternalLotID* (e.g., `PL01-L02-20240718-0001`) to resolve the ambiguity.  
4. The plant’s internal systems automatically map the original lot number to the new, unique ID for all downstream processes (inventory, traceability, recalls, etc.).

### 3.4. Automation

* Add a tiny service or script that runs each time a new lot starts:  
  * It generates the `InternalLotID`.  
  * It writes an entry into the *disambiguation table*.  
  * It writes the new log file to the uniquely named folder.

* The script also checks whether an `OriginalLotID` already exists for the plant+quarter+line. If it does, it appends a suffix (e.g., `-A`, `-B`) to keep the internal ID unique.

### 1. The New Taxonomy

#### A. The New Lot-ID Format (The "Identity")
The current 4-digit counter is insufficient because it lacks a "Line Component." The new Lot-ID must be globally unique across the entire facility, regardless of which line produced it.

**Proposed Format:** `[LineID]-[YYQ#]-[Sequence]`
*   **LineID:** A single letter or number (e.g., `A`, `B`, `C` or `1`, `2`, `3`).
*   **YYQ#:** Year and Quarter (e.g., `24Q1` for 2024, Q1). This prevents the "resetting" issue from causing collisions across years and provides temporal context.
*   **Sequence:** A 4-digit padded counter (e.g., `0001`).

**Example:** A lot produced on Line 2 in the first quarter of 2024 would be **`2-24Q1-0001`**. Even if Line 1 produces something at the same time, its ID will be `1-24Q1-0001`, ensuring zero collision.

#### B. The File Naming Convention (The "Metadata")
Files must be self-describing so an auditor can identify the contents from a file list without opening the file. We will use an ISO 8601-based timestamp to ensure chronological sorting.

**Proposed Format:** `YYYYMMDD_LineID_LotID.csv`
*   **Example:** `20240215_L2_2-24Q1-0001.csv`

#### C. The Folder Hierarchy (The "Structure")
To prevent directory clutter and simplify backups, we will implement a nested structure:
`[Root] > [Year] > [Quarter] > [Line_ID] > [Files]`

**Resulting Path:**
`\\FileServer\USDA_Logs\2024\Q1\Line_2\20240215_L2_2-24Q1-0001.csv`

### 3. Remediation of Ambiguous Historical Data
Since the product has already shipped under the ambiguous numbers, **we cannot rename the files**, as this would break the "Chain of Custody" between the physical product (labeled `0001`) and the digital record. 

Instead, we will perform a **"Data Reconciliation & Reconciliation Report"** to create a legally defensible audit trail.

**The Process:**
1.  **Preservation:** Move all current `lot_log.csv` files into a restricted folder named `ARCHIVE_PRE_REFORM_AMBIGUOUS_DATA`. **Do not rename them.**
2.  **Metadata Extraction:** Use a script to extract the "Date Created" and "Date Modified" timestamps from the files, along with the file size.
3.  **Cross-Referencing (The Reconciliation):** We will map these timestamps against the plant's **Physical Production Logs** (the paper or digital shift logs that record which line was running at what time).
    *   *Example:* If `lot_log.csv` (created at 10:05 AM) is ambiguous, but the Line 1 shift log shows Line 1 was running a batch at 10:05 AM, we have a mathematical link.
4.  **The Reconciliation Report:** We will generate a PDF report titled *"Lot Traceability Reconciliation: [Date Range]."* This report will state: 
    > "Due to the legacy numbering scheme, Lot #0001 (Q1) was duplicated across Lines 1 and 2. Based on file creation timestamps and production logs, we have identified the specific line for each shipment: [List of Shipments vs. Lines]."
5.  **The Result:** When an auditor asks, "How do you know which 'Lot 0001' this sample came from?", you present the **Reconciliation Report**. This demonstrates "proactive corrective action"—a key metric in USDA audits—showing that you identified a non-conformance and implemented a controlled, documented way to resolve it.

### Proposal: Lot-Tracking Taxonomy and File Naming Strategy

**Objective:** Eliminate filename overwrites, resolve lot-number collisions, and establish a self-describing, audit-compliant file/folder taxonomy that satisfies USDA traceability requirements.

#### 1. Proposed Taxonomy

We recommend a two-tier taxonomy: a **Lot-ID structure** that enforces uniqueness across lines, and a **File/Folder naming convention** that captures context without requiring file access.

**A. Lot-ID Format (Scanner Software Configuration)**
The current 4-digit counter creates collisions because it is not scoped to the production line. We must incorporate the Line ID and Quarter into the Lot ID to guarantee global uniqueness while preserving the plant's quarterly reset workflow.

*   **New Format:** `LOT-{LinePrefix}-{QuarterCode}-{Sequence}`
*   **Examples:**
    *   Line 1, Q3, 5th Lot: `LOT-L1-Q3-0005`
    *   Line 2, Q3, 5th Lot: `LOT-L2-Q3-0005`
*   **Benefits:**
    *   **Collision-Free:** `L1` and `L2` prefixes ensure physical lots with the same sequence number never share an ID.

    *   **Self-Describing:** An auditor can identify the line, lot, and exact scan time by inspecting the filename alone.
    *   **No Overwrites:** The timestamp and Lot-ID prevent the "overwrite" behavior caused by generic filenames.

Instead of a single shared folder, implement a hierarchical structure to group logs logically and simplify retrieval.

*   **Structure:** `C:\USDA\LotLogs\{Year}\{Quarter}\`
*   **Workflow:**
    *   Scanners write files into the current quarter's folder.

## 2.  New Naming & Folder Taxonomy  

### 2.1  High‑level folder hierarchy  

```
/<PlantCode>/                     ← Root for the facility (e.g. “PoultryCo”)
   /YYYY/                        ← Year (UTC) – immutable, searchable
      /MM/                       ← Month (01‑12) – immutable
         /DD/                    ← Day (01‑31) – immutable
            /L{L:01‑03}/       ← Line identifier (L01, L02, L03) – 2‑digit zero‑padded
               /Lot{Quarter}{LotSeq:00000}/   ← Unique lot folder (see below)
                  lot_log_{UTC_timestamp}.csv
```

**Explanation of tokens**

| Token | Example | Meaning |
|-------|---------|---------|
| **PlantCode** | `PC01` | Plant‑wide identifier (can be a 2‑digit plant code, location code, or facility name). |
| **YYYY / MM / DD** | `2025 / 09 / 18` | Full ISO date (UTC) of the *scan‑log creation* – guarantees uniqueness even if a line restarts on the same day. |
| **L{L:01‑03}** | `L02` | Production line identifier (01, 02, 03). Zero‑padded to keep sorting alphabetical = chronological. |
| **Lot{Quarter}{LotSeq:00000}** | `LotQ1_00001` | *Quarter* (`Q1`, `Q2`, `Q3`, `Q4`) + *Sequence* – a 5‑digit counter that is **global across all lines** (see §2.3). |
| **lot_log_{UTC_timestamp}.csv** | `lot_log_20250918_143210Z.csv` | The actual file name. The timestamp is the moment the scanner started writing the log (ISO‑8601‑compatible, with trailing `Z` for UTC). |

### 2.2  Full filename syntax  

```
lot_log_YYYYMMDD_HHMMSSZ_L{L:01-03}_LotQ{X}_S{Seq:00000}.csv
```

**Broken down:**

| Segment | Example | Length | Content |
|---------|---------|--------|---------|
| `lot_log_` | `lot_log_` | 8 | Literal prefix – easy to grep on. |
| `YYYYMMDD_HHMMSSZ` | `20250918_143210Z` | 15 | UTC timestamp to the second; the trailing “Z” makes it clear the value is UTC. |
| `_L{L:01-03}` | `_L02` | 3 | Line identifier (2‑digit). |
| `_LotQ{X}` | `_LotQ1` | 5 | Quarter token (`Q` + quarter number). |
| `_S{Seq:00000}` | `_S00001` | 6 | **Global lot sequence** – a 5‑digit, zero‑padded counter that never repeats for the entire plant. |
| `.csv` | `.csv` | 4 | Extension. |

**Full example:**  

```
lot_log_20250918_143210Z_L02_LotQ1_S00001.csv
```

All fields are visible **without opening the file**, enabling a compliance officer to:

* Verify that the file belongs to the correct quarter (`LotQ1`) and line (`L02`).
* Confirm the exact second the scan began (`20250918_143210Z`).
* Identify the unique lot sequence (`S00001`) that is guaranteed never to repeat across the plant.

## 3.  Lot‑Number Taxonomy – Preventing Collisions  

### 3.1  From “local 4‑digit counter” to a **plant‑wide unique lot sequence**  

| Old approach | New approach |
|--------------|--------------|
| Each line increments a 4‑digit counter that resets every quarter (`0001 → 9999`). | A **single plant‑wide monotonic counter** (5‑digit, zero‑padded) is allocated by the MES when a new lot is started on *any* line. The counter is stored in a central database and never resets within the quarter (or ever). |
| Result: two lines could generate `0042` in the same quarter → same lot number. | Result: lot numbers look like `S00001`, `S00002`, … globally; they are unique across all lines and all quarters. |

**How it works in practice**

1. **Lot‑creation request** – When a line’s operator scans the first barcode for a new lot, the scanner sends a *lot‑initiation* message to the MES.  
2. **MES assigns a global sequence** – The MES looks up the next unused 5‑digit counter (e.g., `S00001`) and writes it into the lot header.  
3. **Filename generation** – The scanner immediately creates the filename using that sequence (`_S00001`).  
4. **Persistence** – The same sequence is embedded in the CSV header (mandatory field) so that downstream systems can trace back to the same lot even if the file is moved.

Because the counter is monotonic **across the whole plant**, the chance of two lines ever receiving the same sequence number is **zero**, eliminating the audit‑failure scenario.

### 3.2  Quarter‑level reporting  

The quarter (`Q1`‑`Q4`) is encoded in the folder name (`LotQ1`, `LotQ2`, …). This enables:

* **Automatic quarterly roll‑up** – a simple directory scan returns all lot folders for `LotQ1`.  
* **Retention policies** – the plant can archive an entire quarter by deleting the top‑level `YYYY/MM/DD/L{L}` trees older than X months, knowing that each folder name already contains the quarter token.

### 3.3  Optional checksum for integrity  

To satisfy USDA audit requirements for data integrity, the filename can optionally end with a **32‑bit CRC** derived from the filename contents (excluding the checksum token). Example:

```
lot_log_20250918_143210Z_L02_LotQ1_S00001_6F2A.csv
```

The checksum token is not required for uniqueness but can be added automatically by the scanner if the plant wishes.

* Auditors can verify that each ambiguous lot was assigned a unique canonical ID, satisfying the “traceability” requirement without touching the on‑disk files.
