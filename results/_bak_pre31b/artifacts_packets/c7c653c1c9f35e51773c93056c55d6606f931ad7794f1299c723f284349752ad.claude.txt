### Regex Pattern and Classification

The following Python regular expression can be used with `re.fullmatch` to classify the given test strings:

```python
import re

pattern = r"^TXN-\d{10}-[A-Z]{3}$"

test_strings = [
    "TXN-0048291344-USD",
    "TXN-9999999999-EUR",
    "TXN-004829134-USD",
    "TXN-0048291344-usd",
    "TXN-00482913445-USD",
    "TXN-0048291344-USDX",
    "TXN0048291344-USD",
]

for s in test_strings:
    if re.fullmatch(pattern, s):
        print(f"{s} -> MATCH")
    else:
        print(f"{s} -> NO MATCH")
```

### Explanation

The regular expression `r"^TXN-\d{10}-[A-Z]{3}$"` breaks down as follows:

- `^` asserts the start of the line.
- `TXN-` matches the literal string "TXN-".
- `\d{10}` matches exactly 10 digits.
- `-` matches a hyphen.
- `[A-Z]{3}` matches exactly 3 uppercase letters.
- `$` asserts the end of the line.

### Impact of Using `re.search` Instead of `re.fullmatch`

If we use `re.search` instead of `re.fullmatch`, the regex pattern would still match the start of the string correctly due to the `^` anchor. However, `re.search` does not require the match to cover the entire string; it only needs to find a match somewhere in the string.

For test string 6, `TXN-0048291344-USDX`, using `re.search` instead of `re.fullmatch` would change the classification from "NO MATCH" to "MATCH" because `re.search` would find a match for the pattern `r"^TXN-\d{10}-[A-Z]{3}$"` at the start of the string, ignoring the extra character `X` at the end.

The reason is that `re.search` does not enforce the `$` anchor, which asserts the end of the line. Therefore, it would match the prefix `TXN-0048291344-USD` and return a match, even though the string has additional characters after the match.

To avoid this, using `re.fullmatch` or including the `$` anchor ensures that the entire string must match the pattern, preventing incorrect classifications due to extra characters at the end of the string.
