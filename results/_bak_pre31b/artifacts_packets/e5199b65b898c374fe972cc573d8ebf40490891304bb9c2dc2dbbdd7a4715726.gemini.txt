# Backup & DR Gap Analysis: 40-Attorney Law Firm Case Management

**Date:** October 26, 2023
**Subject:** Critical Infrastructure Risk Assessment & Remediation Plan

## 1. Gap Analysis Against Requirements

The current architecture presents critical vulnerabilities against the firm's Malpractice Insurance policy (RPO $\le$ 4 hrs, RTO $\le$ 8 business hours) and modern ransomware threats.

### Gap 1: RPO Violation (Recovery Point Objective)
*   **Requirement:** Max 4-hour data loss window.
*   **Current State:** Nightly full backup.
*   **Gap:** Assuming backup occurs at 00:00, a failure at 10:00 results in **22 hours of data loss** (cases, billing, communications). This violates the insurance policy and exposes the firm to significant financial liability for unrecorded work.

### Gap 2: RTO Violation & Unknown Recovery (Recovery Time Objective)
*   **Requirement:** System restorable within 8 business hours to meet court deadlines.
*   **Current State:** No restore tested in 18 months.
*   **Gap:** Recovery is assumed, not proven. Restoring a 40-attorney SQL database involves complex dependencies, license validation, and potential hardware replacement. Without documented runbooks and tested procedures, the actual RTO is **unknown and likely >48 hours**.

### Gap 3: Ransomware Single Point of Failure (SPOF)
*   **Requirement:** Resilience against encryption of production *and* backup targets.
*   **Current State:** Backup NAS is co-located in the same server closet and **domain-joined** via a domain service account.
*   **Gap:** This is the critical failure point. If attackers gain admin access to the VM (via phishing or vulnerability), they possess the same network credentials required to mount the NAS. **They can encrypt or delete the backups immediately.** This replicates the peer firm's failure exactly.

### Gap 4: Backup Integrity/Verification
*   **Requirement:** Confirmed recoverability.
*   **Current State:** No restore testing in 18 months.
*   **Gap:** "Backups" may be corrupt due to silent SQL corruption, hardware bit-rot, or failed write operations. The firm is operating under the false assumption that backups are valid.

### Gap 5: 3-2-1 Rule Violation
*   **Requirement:** Offsite/Immutable copies.
*   **Current State:** Only local NAS copy.
*   **Gap:** Total lack of geographic separation. A physical disaster (fire/flood in the server closet) or local network compromise wipes both production and backups simultaneously.

---

## 2. Blast Radius Quantification (If Ransomware Hits Now)

If the firm is hit by ransomware before these gaps are closed, the impact is not just IT downtime; it is business existential:

*   **Data Loss:** Up to 24 hours of case files and billing records permanently encrypted/wiped (RPO breach).
*   **Downtime:** Estimated **3 to 5 days** to manually rebuild SQL, re-attach data, and verify integrity (RTO breach).
*   **Financial Impact:**
    *   **Lost Billable Hours:** 40 attorneys $\times$ 3 days $\times$ 20 hours/day $\times$ $350/hr avg. rate = **~$840,000 in lost revenue.**
    *   **Ransom Cost:** Likely $50k - $150k (if paid) or $0 (if not, but data is lost).
    *   **Malpractice Insurance:** Potential **claim denial** if the firm cannot prove they met their contractual RPO/RTO obligations for client deadlines.
*   **Reputational:** Breach of privileged client communications (attorney-client privilege) triggers mandatory notification laws and potential litigation from clients.

---

## 3. Remediation Plan (Priority Order)

### Phase 1: Immediate Isolation & Immutability (Weeks 1-2)
**Goal:** Break the credential trust chain.
1.  **Implement Immutable Cloud Storage:** Move backups to an S3-compatible Object Storage bucket (e.g., Azure Blob, AWS S3, Backblaze B2) with **Object Lock/WORM** enabled. This ensures that even if domain credentials are stolen, backups cannot be deleted or encrypted by attackers.
2.  **Remove Domain Credentials:** Reconfigure backup software to use a unique, local administrative account for the NAS (if keeping it) or, preferably, **disable the NAS for backups entirely** until immutable storage is online.
3.  **Increase Backup Frequency:** Switch from nightly to **hourly incremental snapshots** or continuous SQL log backups to meet the 4-hour RPO requirement.

### Phase 2: Recovery Verification (Weeks 3-4)
**Goal:** Prove RTO is met.
1.  **Automated Restore Testing:** Configure backup software to perform a "sanity check" restore of a random file/database weekly to a sandbox environment.
2.  **Document Runbooks:** Create step-by-step recovery guides for SQL VM restoration, including failover to the immutable cloud backup.
3.  **Hardware Provisioning:** Ensure the DR site (or cloud VM) is pre-provisioned or has a "warm standby" to ensure the 8-hour RTO is technically feasible.

### Phase 3: Long-Term DR Architecture (Month 2+)
**Goal:** Business Continuity.
1.  **Site Failover:** Establish a secondary SQL cluster (or cloud-based DR instance) that can take over if the primary VM is lost.
2.  **Audit & Pen Test:** Conduct a security audit specifically focused on lateral movement to backup infrastructure.

---

## 4. Pre-Change Safeguards (Critical "Do Not Delete" Protocol)

**DO NOT** modify or delete the current backup regime until the new system is fully validated. The current configuration is "bad," but it is the only thing the firm currently has.

**Step-by-Step Validation Protocol:**

1.  **Parallel Deployment:** Install the new Backup Software and connect it to the **Immutable Cloud Target** while the old NAS configuration remains active.
2.  **Dual-Backup Run:** Run the new backup schedule simultaneously with the old nightly backup for at least 7 days.
3.  **Sandbox Restore Drill:**
    *   Select a random backup from the **new** system (e.g., a file from 48 hours ago).
    *   Restore it to a **non-production** VM.
    *   Verify data integrity (SQL check, file permissions, client data).
    *   *Only if this succeeds, proceed.*
4.  **RTO Simulation:** Time the restore process from the new system. If it takes >8 hours, tune the infrastructure before touching the old backups.
5.  **Decommissioning:** Once the new system has successfully passed **two full restore drills** and meets RPO/RTO metrics, *then* archive the old NAS backups and remove domain credentials.

**Summary:** The current backup strategy is a single point of failure that violates the firm's insurance policy. Immediate action must focus on **immutability** to stop the ransomware SPOF, followed by **frequency increases** to meet RPO, and finally **testing** to validate RTO. Do not break the current chain until the new one has been proven to work.

*   **No Offsite/Cloud Copy:** If the building is compromised, there is no copy of the data anywhere else in the world.
*   **Testing Gap:** 18 months without a restore test means the backup integrity is a "guess." Silent data corruption (bit rot) or failed backups are possible and undetected.

## 5. Mandatory Pre‑Change Verification Step

**Before any modification to the existing backup regime is enacted, the following must be completed and documented:**

1. **Extract & Archive a “Golden” Backup Set**  
   - Pull the most recent full backup (and any existing transaction logs) to an **isolated, read‑only medium** (e.g., encrypted external SSD or a cloud bucket with versioning).  
   - **Hash** the files (SHA‑256) and store the manifest securely.

2. **Perform a Full End‑to‑End Restore Test**  
   - Spin up a **dedicated test VM** on a separate network segment.  
   - Restore the golden backup **to a point‑in‑time** (e.g., 12 hours prior) using the restored logs.  
   - Validate:  
     - Database integrity (`DBCC CHECKDB`).  
     - Application functionality (case‑management UI, billing reports, privilege‑communication access).  
     - Data completeness (sample case files, billing records).  
   - Record **restore duration**, any errors, and required manual steps.

3. **Obtain Formal Sign‑Off**  
   - Legal & IT leadership sign a **“Backup Validation Acceptance”** document confirming that the existing backup can be successfully restored and is **known‑good**.

4. **Document the Current State**  
   - Capture configuration details (NAS model, network VLANs, service account permissions, backup schedule, retention policy).  
   - Store this documentation in a **version‑controlled repository** (e.g., Git) for audit trails.

*Only after these steps are completed should the migration to the new, more resilient backup architecture proceed.* This safeguards against the scenario where the old backups are purged (e.g., after 14‑day retention) and the newly‑implemented process turns out to be defective or incompatible.

### 3. Remediation Plan (Priority Order)

**Phase 1: Immediate Hardening (Days 1-3)**
1.  **Isolate Backup Credentials:** Remove Domain join from the NAS immediately. Change backup service accounts from Domain credentials to local, high-entropy passwords or Managed Identities with strict scope.
2.  **Network Segmentation:** Move NAS to an isolated VLAN or DMZ with no inbound access from the production network. Allow access only from the backup job server via a strictly firewalled rule.
3.  **Immutable Snapshot:** If the backup software supports it, enable "immutable" snapshots or read-only modes immediately to prevent encryption.

**Phase 2: RPO/RTO Compliance (Weeks 1-4)**
1.  **Implement SQL Transaction Log Backups:** Configure frequent SQL Log backups (every 15 mins) to a separate target to achieve **RPO < 1 Hour**.
2.  **Offsite/Cloud Replication:** Deploy a cloud-native backup solution (e.g., Veeam CloudConnect, Azure Backup, AWSBackup) that replicates to an immutable cloud storage bucket (Object Lock / WORM). This satisfies **Offsite** and **Immutability** requirements.
3.  **Instant Restore Capability:** Implement a virtualization layer (e.g., Veeam Backup & Replication, Commvault) capable of "Instant Restore" or VM-level rollbacks to meet the **RTO ≤ 8 Hours**.

**Phase 3: Resilience & Air Gap (Weeks 4-8)**
1.  **Air Gap Solution:** Deploy an air-gap solution (e.g., USB-disconnected NAS, Kaspersky K10, or cloud with offline keys) that is physically or cryptographically unreachable from the network.

1.  **Automated Restore Testing:** Schedule monthly restore tests to a non-production environment.
