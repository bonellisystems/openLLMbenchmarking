```bash
SOURCE_DIR="/data/freezer_logs/"
ARCHIVE_DIR="${SOURCE_DIR}archive/"

# Create archive directory if it doesn't exist
mkdir -p "$ARCHIVE_DIR"

# Process files older than 7 days
while IFS= read -r -d '' file; do
    # Skip if already compressed (check if .gz exists in archive)
    archive_path="${ARCHIVE_DIR}/$(basename "$file").gz"
    if [[ -f "$archive_path" ]]; then
        echo "Skipping already archived: $file"
        continue
    fi

    # Compress and remove only if successful
    if gzip -c "$file" > "$archive_path"; then
        rm -f "$file"
        echo "Archived: $file -> $archive_path"
    else
        echo "Compression failed: $file" >&2
    fi
done < <(find "$SOURCE_DIR" -maxdepth 1 -name "*.csv" -mtime +7 -print0)
```

This ensures data is never lost during compression failures.

```bash
#!/usr/bin/env bash
# archive_freezer_logs.sh
# Safely archives CSV logs older than 7 days from the freezer monitoring system.
# Designed for daily cron execution with strict data integrity guarantees.

set -o pipefail

SRC_DIR="/data/freezer_logs"
ARCH_DIR="${SRC_DIR}/archive"

# Ensure the archive directory exists; abort if we can't create it
mkdir -p "$ARCH_DIR" || { echo "FATAL: Cannot create archive directory: $ARCH_DIR" >&2; exit 1; }

# Find CSV files directly inside SRC_DIR, modified more than 7 days ago.
# -print0 + read -d '' safely handles spaces, newlines, and special characters.
find "$SRC_DIR" -maxdepth 1 -type f -name "*.csv" -mtime +7 -print0 | while IFS= read -r -d '' file; do
    base=$(basename "$file")
    dest="${ARCH_DIR}/${base}.gz"
    tmp_dest="${dest}.tmp"

    echo "Processing: ${base}"

    # Compress to a temporary file, then verify integrity.
    # Both commands must succeed (&&) before proceeding.
    if gzip -c "$file" > "$tmp_dest" 2>/dev/null && gzip -t "$tmp_dest" 2>/dev/null; then
        # Atomically move verified archive into place
        mv "$tmp_dest" "$dest"
        # Only delete the irreplaceable original after successful archiving
        rm -f "$file"
        echo "  Archived successfully."
    else
        echo "  FAILED: Archive creation/verification failed for ${base}. Original preserved." >&2
        rm -f "$tmp_dest"
    fi
done

exit 0
```

### Explanation of the Two Naive Bugs & How This Script Avoids Them

#### (a) Filename Space Handling Bug
**Naive Approach:** Scripts often iterate using `for f in /data/freezer_logs/*.csv; do` or `for f in $(ls *.csv); do`. Both rely on the shell's default word splitting (`$IFS`), which splits on spaces, tabs, and newlines. A file named `Freezer 3 Log.csv` gets split into three separate tokens: `Freezer`, `3`, and `Log.csv`. The loop then attempts to process non-existent files, throws errors, and may accidentally corrupt or delete unrelated files.

**How This Script Avoids It:** 
It uses `find ... -print0` which terminates each filename with a null byte (`\0`) instead of a newline or space. The `while IFS= read -r -d '' file` construct reads until the null byte, preserving the exact filename regardless of spaces, newlines, or glob characters. This is the POSIX-compliant, production-safe pattern for processing arbitrary filenames in Bash.

#### (b) Premature Deletion on Compression Failure Bug
**Naive Approach:** Scripts typically run `gzip "$file"` or `gzip -c "$file" > "$dest"` and immediately follow with `rm "$file"`. If `gzip` fails mid-run (due to disk full, permission error, I/O interrupt, or corrupted source), the original file is deleted anyway. You're left with a missing or truncated `.gz` file and no way to recover the irreplaceable temperature data. Additionally, redirecting directly to `$dest` (`>`) truncates the destination file *before* compression starts, so a crash leaves a zero-byte or partial archive in the final location.

**How This Script Avoids It:**
1. **Temp File Buffering:** Compression writes to `${dest}.tmp` instead of the final path. If `gzip` crashes or is killed, the final archive path is untouched.
2. **Explicit Verification:** `gzip -t "$tmp_dest"` cryptographically verifies the compressed stream's integrity. The `&&` operator ensures the deletion step is only reached if *both* compression and verification exit with status `0`.
3. **Atomic Replacement:** `mv "$tmp_dest" "$dest"` is atomic on the same filesystem, ensuring the archive directory never contains a half-written file.
4. **Conditional Deletion:** `rm -f "$file"` is placed *inside* the success branch. If any step fails, the script logs the error, cleans up the temp file, and leaves the original untouched, preserving critical biotech data. The script also intentionally omits `set -e` so a single failed file doesn't abort the entire cron job, allowing safe re-runs.

### Script: `archive_freezer_logs.sh`

```bash
#!/bin/bash

# Configuration
SOURCE_DIR="/data/freezer_logs"
ARCHIVE_DIR="$SOURCE_DIR/archive"

# Ensure the archive directory exists
mkdir -p "$ARCHIVE_DIR"

# Check if source directory is accessible
if [ ! -d "$SOURCE_DIR" ]; then
    echo "Error: Source directory $SOURCE_DIR does not exist."
    exit 1
fi

# Loop over CSV files in the source directory.
# -maxdepth 1: Restricts search to the root of the source directory.
# -type f: Ensures we only target regular files.
# -name "*.csv": Filters for CSV files.
# -mtime +7: Identifies files modified more than 7 days ago.
# -print0: Uses a null character as a delimiter to handle filenames with spaces.
while IFS= read -r -d '' file; do
    # Determine the target path in the archive directory.
    # We append .gz to the original filename.
    target_path="$ARCHIVE_DIR/$(basename "$file").gz"

    # Attempt to compress the file and write directly to the archive location.
    # gzip -c reads from stdin and writes compressed data to stdout.
    if gzip -c "$file" > "$target_path"; then
        # Compression succeeded.
        # Remove the original file.
        rm "$file"
        echo "[$(date '+%Y-%m-%d %H:%M:%S')] Archived: $(basename "$file")"
    else
        # Compression failed.
        # CRITICAL: Do not delete the original file.
        # Clean up any partially written archive file to maintain directory hygiene.
        if [ -f "$target_path" ]; then
            rm "$target_path"
        fi
        echo "[$(date '+%Y-%m-%d %H:%M:%S')] ERROR: Failed to archive $(basename "$file"). Original preserved."
    fi
done < <(find "$SOURCE_DIR" -maxdepth 1 -type f -name "*.csv" -mtime +7 -print0)
```

### Explanation of Avoided Naive Bugs

**1. Iterating over filenames containing spaces**
*   **The Naive Bug:** A common mistake is using a `for` loop with a glob pattern that is not properly quoted, or parsing the output of `ls` (e.g., `for f in *.csv` or `for f in $(ls *.csv)`). In Bash, spaces act as word separators (delimiters). If a file is named `Freezer 3 Log.csv`, an unquoted loop will break this name into three separate items: `Freezer`, `3`, and `Log.csv`. This causes the script to fail to locate the files and process them as individual, non-existent arguments.
*   **How this Script Avoids It:** The script uses the `find` command with the `-print0` flag, which outputs filenames delimited by a null character (`\0`) instead of spaces or newlines. This output is fed into a `while` loop using `read -d ''`. The `-d ''` flag tells `read` to use the null character as the delimiter, allowing the variable `file` to safely capture the entire path—including internal spaces—without splitting it.

**2. Deleting source files when compression fails**
*   **The Naive Bug:** A naive script might execute commands sequentially without checking the success of the previous step (e.g., `gzip file.csv; rm file.csv`). If `gzip` fails due to a system error (such as a disk being full), the script continues to the next line and executes `rm`. This permanently deletes the original data before a valid backup copy was created. Since these are "irreplaceable sponsor-sample" logs, this results in permanent data loss.
*   **How this Script Avoids It:** The script uses an `if` statement to evaluate the exit status of the compression command (`gzip -c ...`). The `rm` command is strictly placed inside the `if` block, meaning it only executes if the compression command returns a success status (exit code 0). If compression fails, the script enters the `else` block, preserves the original file, and cleans up any partial data, ensuring data integrity is never compromised.

```bash
#!/usr/bin/env bash
# archive_freezer_logs.sh
# --------------------------------------------------------------
# Daily cron job for a biotech lab's ultra‑low‑temperature freezer
# monitoring system.  Moves CSV logs older than 7 days to an
# archive folder, gzip‑compresses them, and only then deletes the
# originals.  Handles filenames that contain spaces.
# --------------------------------------------------------------

set -euo pipefail      # abort on un‑set variables, unset pipefail, or any error
IFS=$'\n'              # split only on newlines (protects against word‑splitting)

# Directories
SRC_DIR="/data/freezer_logs"
ARCHIVE_DIR="/data/freezer_logs/archive"

# Ensure the archive directory exists (create if missing, no error if it already exists)
mkdir -p "$ARCHIVE_DIR"

# 7 days in seconds (86400 * 7)
SEVEN_DAYS_AGO=$(( $(date +%s) - 86400 * 7 ))

echo "[$(date)] Starting archive run..."

# Iterate over *only* the .csv files that sit directly in $SRC_DIR
#   -type f      : regular files only
#   -name "*.csv": match the extension (hidden files like .hidden.csv are ignored)
#   -print0      : output filenames followed by a null byte (safe for spaces/newlines)
#   -mtime +6    : modification time > 6 days ago  (i.e. > 7 days old)
#   -daystart    : makes -mtime count from the start of the current day,
#                  giving a clean “full‑day” boundary.
while IFS= read -r -d '' file; do
    # Compute the relative path inside $SRC_DIR for the archive name
    # Example: /data/freezer_logs/Freezer 3 Log.csv  ->  Freezer 3 Log.csv.gz
    base=$(basename "$file")
    gz_name="${base%.csv}.gz"

    # Full destination path
    dest="${ARCHIVE_DIR}/${gz_name}"

    echo "Processing: $file"

    # ----------------------------------------------------------
    # 1. Attempt gzip compression.
    #    -N   : store original filename & timestamp inside the .gz file
    #    -c   : write to stdout (so we can redirect)
    #    >    : redirect to $dest (clobber if exists – idempotent)
    # ----------------------------------------------------------
    if gzip -N -c "$file" >"$dest"; then
        echo "  → Compression succeeded → $dest"
        
        # ----------------------------------------------------------
        # 2. Only after a successful compression do we remove the source.
        #    -f   : ignore “file not found” (harmless if the file vanished
        #           between gzip and rm, but we never get here unless gzip succeeded)
        # ----------------------------------------------------------
        rm -f "$file"
        echo "  → Original removed."
    else
        echo "  → *** Compression FAILED for $file – leaving original intact! ***"
        # Do NOT delete the file; we simply continue with the next one.
    fi
done < <(find "$SRC_DIR" -type f -name "*.csv" -mtime +6 -daystart -print0)

echo "[$(date)] Archive run completed."
```

## Why this script avoids the two common bugs

### (a) Iterating over filenames that contain spaces

**Naïve approach (buggy):**
```bash
for file in $(ls /data/freezer_logs/*.csv); do
    # …process $file…
done
```
*Problem:* `ls` (or a plain `for … in …`) splits the word list on **any** whitespace (space, tab, newline). A filename like `Freezer 3 Log.csv` becomes two tokens: `Freezer` and `3`. The subsequent commands then operate on nonexistent files or behave unexpectedly.

**What the correct script does:**
```bash
find "$SRC_DIR" -type f -name "*.csv" -mtime +6 -daystart -print0 |
    while IFS= read -r -d '' file; do … done
```
*Explanation:*
- `find … -print0` writes each filename followed by a **NULL** character (`\0`). NULL never appears in a normal filename, so the list is unambiguous.
- The `read -d ''` primitive reads exactly up to the next NULL, preserving spaces, tabs, even newlines, and other weird characters.
- `set -euo pipefail` and the explicit `IFS=$'\n'` guard against any accidental word‑splitting later in the script.

Thus the script reliably handles any CSV file, regardless of how the monitoring software names it.

---

### (b) Deleting a source file even when compression failed

**Naïve approach (buggy):**
```bash
gzip "$file"
rm "$file"          # always delete, even if gzip exited with a non‑zero status
```
*Problem:* If `gzip` encounters a permission error, disk‑full condition, or a corrupted file, it returns a non‑zero exit status. The subsequent `rm` still runs, **permanently discarding** the original log—exactly what the requirement forbids.

**What the correct script does:**
```bash
if gzip -N -c "$file" >"$dest"; then
    rm -f "$file"
else
    echo "Compression FAILED – keeping original."
    # (no rm here)
fi
```
*Explanation:*
- The `if …; then …; else …; fi` block makes the **deletion conditional** on the success of the gzip command.
- `gzip`’s exit status is examined directly (`$?` is implicitly tested by the `if`). If `gzip` fails, the `else` branch runs, prints a warning, and **does not** delete the source file.
- `set -e` (set at the top) would already abort the whole script on any command failure, but we deliberately handle the failure gracefully instead of aborting the entire job. This way, one bad file doesn’t stop archiving all the others.

By coupling the compression success test with the deletion, the script guarantees that **no original log is ever removed unless a valid `.gz` archive exists**—protecting the irreplaceable sponsor‑sample temperature records.
