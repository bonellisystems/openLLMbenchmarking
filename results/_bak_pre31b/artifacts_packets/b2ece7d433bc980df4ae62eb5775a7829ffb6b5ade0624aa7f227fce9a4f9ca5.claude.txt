### Explanation of Avoided Bugs

**(a) Iterating over filenames that break on spaces**
A naive script often uses a pattern like `for file in /data/freezer_logs/*.csv` combined with command substitution, or pipes `find` output to `while read` (e.g., `find ... | while read file`). In Bash, whitespace in filenames triggers **Word Splitting**. If a file is named `Freezer 3 Log.csv`, a naive `read` loop treats this as three separate arguments (`Freezer`, `3`, `Log.csv`), causing the script to process incorrect paths or fail silently.

**How this script avoids it:**
It uses `find -print0` to output filenames separated by null characters instead of newlines. The `while` loop uses `IFS= read -r -d ''` to read until the null delimiter. This preserves the entire filename string exactly as it is, regardless of spaces or special characters.

**(b) Deleting the source file when compression fails**
A naive script might chain commands like `gzip "$file"; rm "$file"`. The `rm` command executes regardless of whether `gzip` succeeded (returned non-zero) because the `;` ignores the exit status of the previous command. If the disk fills up or `gzip` encounters an error, the original log file is deleted, and the data is lost permanently.

**How this script avoids it:**
It uses an explicit conditional check: `if gzip -c "$file" > "$archive_file"; then ...`. The `rm` command is placed inside the `then` block, meaning it only runs if `gzip` exits with status 0. If compression fails, the script does nothing, leaving the original `.csv` file untouched in the source directory for the next scheduled run to attempt again.

```bash
set -uo pipefail

ARCHIVE_DIR="/data/freezer_logs/archive"

mkdir -p "$ARCHIVE_DIR"

find "$SRC_DIR" -maxdepth 1 -type f -name "*.csv" -mtime +7 -print0 | \
while IFS= read -r -d '' csv_file; do
    archive_file="$ARCHIVE_DIR/$(basename "$csv_file").gz"

    # Skip if archive already exists (idempotent; safe for re-runs)
    if [[ -f "$archive_file" ]]; then
        continue
    fi

    # Use a temporary file to prevent partial/corrupt archives on failure
    tmp_archive=$(mktemp "$ARCHIVE_DIR/.tmp_XXXXXX.gz")

    # gzip -c writes to stdout. We redirect to the temp file and verify success.
    if gzip -c "$csv_file" > "$tmp_archive" && [[ -s "$tmp_archive" ]]; then
        mv "$tmp_archive" "$archive_file"   # Atomic rename on same filesystem
        rm "$csv_file"                     # Only delete original after verified success
    else
        rm -f "$tmp_archive"               # Clean up partial/failed temp file
        echo "ERROR: Compression failed for '$csv_file'. Original kept." >&2
    fi
done
```

### Explanation of the Two Common Bugs Avoided

**(a) Space-breaking filename iteration**  
A naive script often uses `for file in /data/freezer_logs/*.csv` or pipes `find` output to `while read file`. Both approaches rely on the default `IFS` (whitespace), causing `Freezer 3 Log.csv` to be split into three separate iterations: `Freezer`, `3`, and `Log.csv`. This results in "No such file or directory" errors or processing of incorrectly named files.  
**How this script avoids it:** It uses `find ... -print0` to terminate each path with a null byte (`\0`), and `while IFS= read -r -d ''` to read exactly until that null byte. This preserves spaces, tabs, and other special characters exactly as they appear on disk.

**(b) Deleting the source file when compression fails**  
Common patterns like `gzip "$file" && rm "$file"` or unconditionally running `rm` after an `gzip -o` command ignore the exit status of the compression step. If the disk is full, permissions are wrong, or the input CSV is corrupted, `gzip` will fail, but the original file is still deleted (or worse, partially overwritten/truncated before the failure is caught), destroying irreplaceable temperature logs.  
**How this script avoids it:** It explicitly checks the exit status of `gzip -c` and verifies the output is non-empty (`-s`). Crucially, it writes to a temporary file first. Only if the temp file is successfully created, non-empty, and moved to the archive directory does it execute `rm "$csv_file"`. This guarantees the original is never touched unless a verified, intact archive exists.

```bash
            # Compression succeeded and archive is valid.
            # Now it is safe to remove the original source file.

            echo "Successfully archived: $filename"
        else
            echo "Error: Archive file $dest_file is empty (data loss risk). Original preserved."
            rm -f "$dest_file" # Clean up the invalid archive
        fi
    else
        echo "Error: Failed to compress $filename. Original preserved."
        # Clean up potential partial/failed archive file
        rm -f "$dest_file"
    fi

done
```

### Explanation of Common Bugs Avoided

The script is designed to specifically mitigate two common failures found in naive backup scripts, particularly when handling "irreplaceable" data like biotech logs.

#### 1. Iterating Over Filenames with Spaces (Word Splitting)
**The Naive Approach:**
A common mistake is iterating over files using command substitution or unquoted globs, for example: `for file in $(ls /data/freezer_logs/*.csv)`.
**Why it breaks:**
In Bash, the output of `ls` or unquoted variables undergoes "word splitting." If a file is named `Freezer 3 Log.csv`, the shell splits this into three separate arguments: `Freezer`, `3`, and `Log.csv`. The script then attempts to process these non-existent filenames, resulting in errors or corrupted archives.
**How this script fixes it:**
The script uses `find` with the `-print0` flag, which separates filenames with a null byte (`\0`) instead of whitespace. It then pipes this into a `while` loop using `read -d ''` (null delimiter). This treats the entire filename—including spaces and newlines—as a single, indivisible string.

#### 2. Premature Deletion (Unsafe Compression)
**The Naive Approach:**
A naive script might run `gzip file.csv` (which replaces the file with `file.csv.gz`) followed immediately by `mv file.csv.gz archive/`. Alternatively, it might run `gzip -c file.csv > archive/file.csv.gz; rm file.csv`.
**Why it breaks:**
If the compression fails (due to a disk full, permission error, or software crash), the source file might be deleted before the archive is fully written. In the worst case, you are left with a truncated, unusable archive file and the original log is gone forever.
**How this script fixes it:**
The script uses "copy mode" compression (`gzip -c`) to write the compressed data to a *new* file in the archive directory while leaving the original source file completely untouched. It then checks the exit status (`$?`) of the gzip command. The `rm` command is strictly conditional; it only executes if the compression command returns a success code (0), ensuring the source file is never deleted unless a valid copy has been confirmed in the archive.

```bash
    # The '&&' operator ensures 'rm' only executes if 'gzip' returns exit code 0.

        rm "$file"
        echo "Successfully archived: $filename"
```
