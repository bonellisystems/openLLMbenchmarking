## Task

The task given to every model in this cohort:

A payments processor uses transaction reference IDs in the exact format
`TXN-` followed by 10 digits, followed by `-`, followed by a 3-letter uppercase ISO currency
code -- for example `TXN-0048291344-USD`.

Construct a single Python regular expression, intended to be used with `re.fullmatch`, that
correctly classifies each of the following 7 test strings as MATCH or NO MATCH:

1. `TXN-0048291344-USD` -> should MATCH
2. `TXN-9999999999-EUR` -> should MATCH
3. `TXN-004829134-USD` -> should NOT match (only 9 digits)
4. `TXN-0048291344-usd` -> should NOT match (lowercase currency code)
5. `TXN-00482913445-USD` -> should NOT match (11 digits)
6. `TXN-0048291344-USDX` -> should NOT match (trailing extra character after the currency
   code)
7. `TXN0048291344-USD` -> should NOT match (missing the hyphen right after TXN)

Give the regex, classify all 7 strings against it, and explain specifically why using
`re.search` with your pattern instead of `re.fullmatch` (or omitting start/end anchors)
would change the correct classification of test string 6.

- `^` – asserts the start of the string (no characters may precede the pattern).  
- `TXN-` – the literal prefix exactly as required.  
- `\d{10}` – exactly ten decimal digits.  
- `-` – a literal hyphen separating the digits from the currency code.  
- `[A-Z]{3}` – exactly three uppercase ASCII letters (the ISO‑4217 currency code).  
- `$` – asserts the end of the string (no characters may follow the pattern).

Because both `^` and `$` are present, the whole input must match the pattern; any extra
characters before, inside, or after the pattern cause `re.fullmatch` to return `None`.

| 1 | `TXN-0048291344-USD`       | Matches `TXN-` + 10 digits + `-` + 3 uppercase letters | **MATCH** |
| 2 | `TXN-9999999999-EUR`       | Same structure, valid digits and currency code | **MATCH** |

### Why `re.search` (or dropping the anchors) would misclassify test string 6

`re.search` looks for **any** substring of the input that matches the pattern; it does **not**
require the match to span the entire string. If we used:

```python
re.search(r"TXN-\d{10}-[A-Z]{3}", "TXN-0048291344-USDX")
```

the engine finds the substring `TXN-0048291344-USD` inside the longer string and returns a
match object, even though the full string contains the extra character `X`.  

Equivalently, if the anchors `^` and `$` were omitted (e.g., `r"TXN-\d{10}-[A-Z]{3}"`),
the same “partial‑match” behavior occurs: the pattern can match a prefix of the string,
leaving unconsumed trailing characters, and `re.search` (or even `re.match` without `$`)
would report a successful match.

Therefore, without the start‑of‑string (`^`) and end‑of‑string (`$`) anchors, **test string 6**
would be incorrectly classified as **MATCH** instead of **NO MATCH**. Using `re.fullmatch`
(or explicitly anchoring with `^` and `$`) guarantees that the entire input must conform to
the exact specification.
