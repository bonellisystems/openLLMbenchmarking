### **1. Duplicate Title Tags on Project Pages**

- **Cause:**  
  The project portfolio pages use a generic title template (e.g., "Our Projects | Firm Name") across all pages, likely due to missing or misconfigured title template in Yoast SEO for the custom post type (e.g., "project"). This results in **34 pages** with identical `<title>` tags, harming SEO by reducing relevance and confusing search engines.

- **Fix:**

  1. Go to **SEO → Search Appearance → Content Types** in Yoast.
  2. Find the "Project" (or similarly named) post type.
  3. Set the **Title template** to:

### **4. Paginated Blog Series Without rel=next/prev or Canonicals**  
**Priority: Medium (Impact: Medium | Effort: Low)**

- **Cause:**  
  **12-page blog series** lacks `rel="next"`, `rel="prev"`, or self-referencing canonicals, causing search engines to treat each page as a near-duplicate. This dilutes ranking signals and may lead to only page 1 ranking.

- **Fix:**  
  1. **Ensure each page has a self-referencing canonical** (Yoast usually does this by default). Verify in page source:  
     `<link rel="canonical" href="https://example.com/blog-series/page/2/" />`
  2. **Add rel=next/prev tags**:
     - Yoast **does not auto-generate** `rel="next"`/`rel="prev"` for custom pagination (e.g., `/page/2/`).
     - Use a plugin like **WP SEO Structured Data Schema** or **Rank Math** (if willing to switch), or add manually via `functions.php`:
       ```php
       function add_pagination_rel_links() {
           if ( is_paged() ) {
               global $wp_rewrite;
               $page = get_query_var('paged') ? get_query_var('paged') : 1;
               $base = get_pagenum_link(1);
               $base = preg_replace('/\/page\/[0-9]+\/?$/', '/', $base, -1);

               if ( $page > 1 ) {
                   echo '<link rel="prev" href="' . esc_url( $base . 'page/' . ($page - 1) . '/') . '" />' . "\n";
               }
               if ( $page < $GLOBALS['wp_query']->max_num_pages ) {
                   echo '<link rel="next" href="' . esc_url( $base . 'page/' . ($page + 1) . '/') . '" />' . "\n";
               }
           }
       }
       add_action('wp_head', 'add_pagination_rel_links');
       ```
  3. Alternatively, consolidate content into a single scrollable page with anchor links if SEO value is low.

- **WordPress/Yoast Specifics:**  
  Yoast lacks native pagination tagging for custom series. Relies on core WordPress pagination and manual or plugin-based fixes.

> ✅ **Impact**: Medium — helps [model] consolidate ranking power across series. Prevents duplication penalties.  
> 💡 **Effort**: Low — small code addition or plugin use.

### 3. Paginated Blog Series (Missing Canonical/rel=next/prev)
**Root Cause**

**WordPress + Yoast Fix**
1. **Yoast Configuration Check:**

### Issue 3: Homepage Largest Contentful Paint (LCP) = 4.8 Seconds
*   **Cause:** Architecture firms rely on high-resolution hero imagery and detailed blueprints.         *   "File optimization" (Minification of CSS/JS).
        *   "Lazy loading offscreen images" (ensure the *hero* image is *not* lazy-loaded, as this kills LCP).
    3.  **Preload Key Asset:** Add a `<link rel="preload" as="image">` tag in the homepage header for the hero image. In WordPress, this can be added to `functions.php` or via a plugin like "Preload Images."
    4.  **Review Render Blocking:** If the theme loads jQuery or slider JS before the hero image, switch to a deferred loading method or a headless slider solution (e.g., Hero Images plugin).
