## Proposed Alerting Strategy: "Persistent Breach" with Auto-Escalation

### 1. Retuned Threshold/Timing Logic: The "Persistent Breach" Rule

The core problem is that defrost and failure share the same **temperature onset** (both rise past -75°C), but they differ in **temporal trajectory** (defrost resolves, failure sustains). A wider static threshold (e.g., -65°C) eliminates defrost false positives but introduces a dangerous gap: if a compressor fails and the temperature lingers at -75°C for the first hour, no alert would fire until it crossed -65°C.

**New Rule:**
*   **Trigger:** Freezer temperature breaches -75°C.
*   **Condition:** Temperature must remain above -75°C for a continuous **15-minute window**.
*   **Action:**
    *   **If temperature returns to -78°C within 15 minutes:** Log as "Defrost Cycle" (Info/No Page).
    *   **If temperature remains above -75°C after 15 minutes:** Fire P1 Page to On-Call.

**Why this works:**
*   **Defrost Safety:** Normal defrost cycles last ~12 minutes and return to baseline. The 15-minute window provides a 3-minute safety buffer for sensor noise while guaranteeing no page for a normal cycle.
*   **Failure Detection:** A genuine compressor failure will not self-resolve. Even if the first 15 minutes look like a defrost curve, the failure will persist, triggering the P1 alert.
*   **Rationale:** This converts the alert from a *static temperature* check to a *state-machine* check, distinguishing defrost from failure based on the absence of recovery rather than the magnitude of the spike.

*   **High-Severity Safety Net:** The -60°C bypass ensures that if the compressor fails catastrophically (rapid temperature rise), the alert is escalated immediately, bypassing the defrost filter entirely.

*   **Threshold Adjustment (-76°C):** We lower the trigger slightly from -75°C to -76°C to catch slow-ramping failures earlier. Since defrost routinely hits -70°C, it will still cross -76°C, ensuring defrost cycles are evaluated by the logic rather than ignored by a higher threshold.

*   **Recovery Suppression (The "Smart" Logic):** This is the core differentiator.

| **Evaporator pressure** (if a pressure transducer exists) | Pressure will fall when the compressor stalls. |
| **Door‑open status** (door‑interlock) | If the door is open *and* temperature rises, the system may be a manual sample‑pull rather than a failure. |
| **Ambient temperature** (lab HVAC) | Sudden ambient spikes can explain brief warm‑ups; they are usually correlated across many freezers. |

**Implementation tip** – feed these values into a simple rule engine:  
`IF (temperature_rule_met OR rapid_rise_rule) AND (compressor_current_drop OR pressure_drop) THEN escalate to P1 immediately`.

### 3.3. Auto‑Escalation / “Page‑Lock”  

- **After a P1 page is generated, the system records a “page‑ticket”** with a unique ID.  
- If the ticket is **acknowledged as “silenced” or “dismissed” without a manual verification step** (e.g., no “Verify sample integrity” click), the system **re‑pages after 5 min** with a higher‑priority channel (SMS + pager).  
- After **three consecutive ignored pages**, the system automatically **opens a ticket** in the lab’s LIMS/IR ticketing system and **notifies the lab manager** via email.

This ensures that engineers cannot silently bury the alarm without *actively* confirming that everything is OK.

### 3.4. “Cold‑Start” Check on System Boot  

When the monitoring service restarts, it should **re‑initialize all timers** and **reset the defrost‑window exclusion list** based on the latest schedule. This prevents a stale “defrost‑in‑progress” flag from inadvertently suppressing a real alarm after a reboot.

## 4. Putting It All Together – Flowchart (textual)

```
Every 1‑minute evaluation per freezer:

1. Read T(t), dT/dt, defrost_status (from PLC), compressor_current.
2. Is Defrost_Status == TRUE?  →  Skip all alarm logic for this minute.
3. If T > -70 °C:
       a) If rise_rate >= 0.45 °C/min for 2×5‑min windows → P1 page.
       b) Else if T stays > -70 °C for >30 min → Warm‑State warning → 30‑min timer.
4. If T > -68 °C and not in defrost window:
       start Warm‑State timer (30 min). If timer expires → P1 page + escalation.
5. If rapid_rise (ΔT >= 1.5 °C in 5 min) AND not in defrost → P1 page (bypass 12‑min rule).
6. If any of the above also satisfies secondary sensor condition (current drop, pressure drop) → raise **high‑severity** alert (immediate page).
7. If alert generated and not acknowledged within grace period → auto‑escalate / ticket.
8. Log all events for trend analysis; feed back into Defrost‑Signature baseline.
```

To solve the problem of alert fatigue while maintaining the safety of irreplaceable samples, we must move away from **point-in-time** thresholding and move toward **state-based** and **trend-based** alerting.

Here is the proposed two-pronged strategy.

### 1. The New Alerting Logic: "Duration-Based Thresholding"
Instead of triggering an alert the moment a sensor hits -74°C, the logic should be changed to a **Duration-Based (or "Sticky") Threshold.**

*   **New Rule:** Trigger a P1 page **ONLY IF** the temperature remains above -75°C for a continuous period of **20 minutes**.
*   **Why this works:** Since the defrost cycle is known to last exactly 12 minutes, a 20-minute window provides a sufficient "buffer" to absorb the normal thermal oscillation. The defrost cycle will spike the temperature, but since it returns to the baseline before the 20-minute timer expires, no page is sent. This eliminates the "noise" that caused the engineers to ignore the alerts.

---

### 2. The Compensating Control: "Rate-of-Change (RoC) Trigger"
A "wider static threshold" (e.g., setting the alert to -65°C) is dangerous because a compressor failure could take hours to reach that temperature, by which time the samples are lost. 

To ensure we catch a genuine failure even if the temperature hasn't reached the 20-minute duration threshold, we implement a **Rate-of-Change (RoC) Trigger.**

*   **The Logic:** Trigger an immediate P1 page if the temperature increases at a rate of **$> X$ degrees per 5 minutes** (where $X$ is calculated based on the historical "slope" of a defrost cycle).
*   **Why this is the "Safety Net":** 
    *   **During a Defrost:** The temperature rise is controlled and follows a predictable, relatively slow curve as the defrost heaters activate.
    *   **During a Compressor Failure:** The temperature rise is often more erratic or follows a different thermal slope. 
    *   **The Benefit:** If a compressor fails, the temperature might only be at -77°C, but if the *speed* at which it is climbing is abnormal compared to a standard defrost cycle, the system identifies the *anomaly in the trend* rather than the *absolute value*. This catches the failure much earlier than a static threshold would.
