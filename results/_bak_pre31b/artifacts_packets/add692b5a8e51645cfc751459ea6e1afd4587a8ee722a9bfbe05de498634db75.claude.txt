Troubleshooting steps are ordered from least to most disruptive, a clear escalation path is given for when the fix is out of the agent's scope, and the answer is calibrated about what genuinely needs remote hands or an on-site visit.

Example character: recommends reimaging a device as the first step for a minor, non-blocking symptom.

### 1. What to Check Before Touching the Corrupted Central Model
**Decision:** Perform non-destructive diagnostics on the file server and Revit environment **before** attempting any repair, extraction, or restoration. Touching a corrupted Revit file can propagate corruption, lock the file permanently, or destroy the only remaining data.

*   **Disk Integrity & File System Health:** Since the server was rebooted unexpectedly, the file system may have dirty states, broken journaling, or bad sectors. *   **Single-User Mode Test:** Attempt to open the central model in **Single-User mode** (Revit > File > Open > select "Single User"). *   **Local File Status:** Verify if the 3 local files referenced in the sync logs still exist and are intact. In Revit worksharing, if the central is lost but locals are clean, the project can sometimes be recovered by re-linking locals or extracting from locals.
*   **File Size & Metadata:** Compare the file size and modification timestamps against the last known good state (or the 10:00 PM backup). A drastic size reduction may indicate a "zeroed" file, while a size spike may indicate append-only corruption.
*   **Isolate the Corruption Scope:** If accessible, check the Revit file properties or use a tool like `RevitFileChecker` (if available) to determine if the corruption is in the geometry database, the coordination settings, or the metadata.

**Justification:**
