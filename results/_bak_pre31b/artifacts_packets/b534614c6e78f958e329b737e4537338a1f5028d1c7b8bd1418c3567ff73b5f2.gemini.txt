**Why the error occurs**

The function `calculate_permit_fee` defines a variable `surcharge` only inside the `if` block:

```python
if square_footage > 5000:
    surcharge = fee_schedule.get("large_project_surcharge")
```

When the function is called with `square_footage = 1200`, the condition `square_footage > 5000` is **false**, so the `if` block is skipped entirely.  
Because `surcharge` is never assigned a value in that case, the name `surcharge` does not exist in the local scope when the line

```python
total = base_fee + surcharge * square_footage / 1000
```

is executed. Python therefore raises an `UnboundLocalError: local variable 'surcharge' referenced before assignment`.

The same error would also appear if `square_footage > 5000` **and** the `fee_schedule` dictionary did not contain the key `"large_project_surcharge"`; `surcharge` would be assigned `None`, and `None * square_footage` would raise a `TypeError`. The traceback shown, however, corresponds to the first situation (the variable is never defined).

---

**Fixed version of the function**

To avoid the error we must ensure that `surcharge` is defined **before** we use it. The usual pattern is to give it a default value (typically `0`) and then adjust it only when the large‑project condition is met. We also explicitly handle the case where the schedule lacks the `"large_project_surcharge"` key by falling back to `0`.

```python
FEE_SCHEDULE = {
    "residential_addition": 150,
    "large_project_surcharge": 2.5,   # optional; may be missing
}

def calculate_permit_fee(permit_type, square_footage, fee_schedule):
    # 1. Get the base fee (raises KeyError if permit_type is missing – that's intentional)
    base_fee = fee_schedule[permit_type]

    # 2. Start with a zero surcharge for all projects
    surcharge = 0.0

    # 3. If the project is large, look up the surcharge; if the key is absent, keep surcharge as 0
    if square_footage > 5000:
        surcharge = fee_schedule.get("large_project_surcharge", 0.0)

    # 4. Compute the total fee.  The surcharge is applied as a per‑1000‑sq‑ft amount.
    total = base_fee + surcharge * square_footage / 1000

    # 5. Return the result rounded to two decimal places
    return round(total, 2)


# Example usage
fee = calculate_permit_fee("residential_addition", 1200, FEE_SCHEDULE)
print(fee)          # → 150.0 (no surcharge)

# Test a large project where the surcharge key exists
fee_large = calculate_permit_fee("residential_addition", 6000, FEE_SCHEDULE)
print(fee_large)    # → 165.0  (150 + 2.5 * 6)

# Test a large project where the surcharge key is missing (fallback to 0)
fee_large_no_surcharge = calculate_permit_fee(
    "residential_addition", 6000, {"residential_addition": 150}
)
print(fee_large_no_surcharge)  # → 150.0 (no surcharge applied)
```

**Key improvements**

1. **Default `surcharge = 0.0`** – guarantees the variable exists in every code path, eliminating the `UnboundLocalError`.
2. **Graceful fallback** – `fee_schedule.get("large_project_surcharge", 0.0)` ensures that if the schedule omits the surcharge entry, the function still works (the surcharge simply becomes zero rather than raising an exception).
3. **Clear logic** – the intent (“apply surcharge only for projects > 5000 sq ft, otherwise none”) is now explicit and safe from undefined‑variable bugs.

### Explanation of the Error

The error `UnboundLocalError: local variable 'surcharge' referenced before assignment` occurs because of the conditional logic used to define `surcharge`.

In Python, when you assign a value to a variable inside an `if` block, that variable is only "bound" (created in memory) if the condition evaluates to `True`. 

For the specific call `calculate_permit_fee("residential_addition", 1200, FEE_SCHEDULE)`:
1. The `base_fee` is successfully set to `150`.
2. The condition `if square_footage > 5000` is checked. Since `1200` is **not** greater than `5000`, the condition is `False`.
3. The code inside the `if` block (where `surcharge` is defined) is **skipped entirely**.
4. When the interpreter reaches line 10 (`total = base_fee + surcharge * ...`), it attempts to look up the value of `surcharge` to perform the multiplication. Because the assignment line was skipped, `surcharge` does not exist in the local scope, triggering the `UnboundLocalError`.

---

### Fixed Code

To fix this, we must ensure `surcharge` is initialized to a default value (zero) before the conditional check. We also use the second argument of `.get()` to provide a fallback of `0.0` in case the `"large_project_surcharge"` key is missing from the dictionary.

```python
FEE_SCHEDULE = {
    "residential_addition": 150,
    "large_project_surcharge": 2.5,
}

def calculate_permit_fee(permit_type, square_footage, fee_schedule):
    # Use .get() for base_fee to handle potential missing permit types gracefully
    base_fee = fee_schedule.get(permit_type, 0)
    
    # 1. Initialize surcharge to 0.0 so it is always defined (handles sq ft <= 5000)
    surcharge = 0.0
    
    if square_footage > 5000:
        # 2. Use .get(key, default) to handle missing "large_project_surcharge" key
        surcharge = fee_schedule.get("large_project_surcharge", 0.0)
    
    # 3. Perform calculation (surcharge will be 0.0 if sq ft <= 5000 or key is missing)
    total = base_fee + (surcharge * square_footage / 1000)
    
    return round(total, 2)

# Test Cases
```
